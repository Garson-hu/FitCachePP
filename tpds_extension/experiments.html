FitCachePP TPDS Extension — Experiments

Structure. FitCachePP is one system. Part 1 measures the whole system (all three mechanisms on) at two scales — §1.1 at 1–16 nodes, §1.2 at 32–256 nodes — plus one job that fills itself and survives a mid-run server restart. Part 2 ablates each mechanism to attribute the result. Every performance cell passes a FitCachePP-vs-Native_mmap_PFS checksum-equality gate (per-rank for the multi-seed GNN bench). Datasets, access patterns, run procedure, and the gate/honesty details: experiments_methodology.html.

Part 1 — Whole system: mmap + prefetch, at two scales

Part 1 runs the whole system — the transparent mmap cache path plus an application fitcache_prefetch() hint that promotes each node's working set ahead of the read. Prefetch replaces the access-aware-placement step: instead of every node staging the full corpus (replicate-all, N×), each node prefetches only its own 1/N partition, so the cluster holds the read set once (1×) while every read is still a warm local mmap. Two scales — §1.1 at 1–16 nodes, §1.2 at 32–256 — each tabling all three workloads side by side: Megatron (dense-sequential) and DINOv2 (sequential vision), both 1×-partitionable, plus GNN (sparse 2-hop gather), the un-partitionable case where prefetch still wins the warm-hit but storage stays N×. Every cell passes a FitCachePP-vs-Native_mmap_PFS per-rank checksum-equality gate.

1.1 — 1–16 nodes DONE

Each node prefetch-promotes its disjoint 1/N partition from Lustre into local NVMe, then mmap-reads it warm. cold→warm = native first (cold) read ÷ FitCachePP warm; warm→warm = native 2nd-epoch (page-cached) warm ÷ FitCachePP warm. 1× cache = the per-node footprint (its partition only), du on NVMe.

1× storage — each node caches only its partition (Megatron 32/N shards × 16 GiB = 256→128→64→32 GiB, du-confirmed at N=4,8; DINOv2 its 8 shards = 4.35 GB), so the cluster holds the read set once vs replicate-all's N×. Correct + warm — every node count passes the per-rank checksum gate. The warm→warm speedup is modest (Megatron 1.9–2.3×, DINOv2 ~1.6×) because at 1× the partition fits node RAM so the native baseline page-caches it too; the cost FitCachePP actually removes is the cold→warm gap (Megatron 5–20.6×: a 925 s first cold read becomes a 60 s warm read). Megatron N=1 (un-partitioned 512 GiB single-node baseline) omitted. GNN — the un-partitionable column. Its 2-hop heterogeneous gather can touch any feature row (the access set is data-dependent, not a contiguous slice), so it cannot be 1×-partitioned: every node holds the whole feature + CSR set (902 GB), and storage stays N× (the N×/node column). Here FCP warm is the NVMe-bound gather — the ~2.67 GB of scattered rows served from the node's local copy, a flat ~86 s — versus the native gather scattered from Lustre; cold→warm is that ratio. Read it as NVMe-warm-flat + native-volatile, not “speedup grows with scale”: the native cold epoch swings with time-of-day Lustre congestion (4419 s at N=2 down to 827 s at N=16) while the local gather stays ~86 s, so the ratio wobbles (9.6–51×) rather than trending. (Once the page cache is warm a re-read drops to ~4 s, but we report the conservative NVMe-bound number.) Every rank's checksum matches Native_mmap_PFS byte-for-byte under the per-rank gate; the pooled cross-rank gate cosmetically reports FAIL only because each rank uses a distinct seed. Source: gnn_scale_ladder/.

1.2 — 32–256 nodes DONE

Same mmap+prefetch setup at scale. Megatron caps at N=64 (its 64-shard corpus → 1 shard/node at N=64); DINOv2 reaches N=256 (996-shard corpus, 3 shards/node). Same columns as §1.1. GNN stays un-partitionable at every scale — each node still holds the whole feat+CSR set (902 GB, N×). Its NVMe-bound warm gather stays flat (~75–87 s) from 32 to 256; the native cold epoch is time-of-day-volatile (576→440→757→973 s), so cold→warm wobbles 5.1–13.0× — again warm-flat + native-volatile, not a scaling trend. Per-rank checksum PASS (the pooled cross-rank gate cosmetically FAILs on per-rank seeds). Source: gnn_scale_ladder/.

Part 2 — Ablations: what each mechanism contributes

Each ablation turns one mechanism off (or compares it against the naive alternative) so the whole-system result is attributed to the right cause.

2.2 — Cache tier: DRAM (tmpfs) vs NVMe DONE

Tier-general (DRAM/tmpfs → PMem → NVMe by remaining capacity). The headline runs were served from the per-node NVMe burst buffer (/mnt/bb). A DRAM-tier datapoint confirms the path also serves from tmpfs at parity (48 warm hits resolve to /tmp, bit-identical checksum 3453497658530916), but that is a cold-start regime: when the working set fits tmpfs the native baseline page-caches it too and the sustained gap washes out. NVMe backs the headline.

2. Glossary

These benchmarks are I/O benchmarks: there is no model forward/backward pass. The "model" is replaced by a deterministic access pattern + a byte-touch that forces every read through the page-fault path. Terms used throughout:

TermMeaning in these experiments
cold (native baseline)First read of a file whose pages are not resident — for Native_mmap_PFS this is an organic read straight from Lustre, run after a page-cache eviction. This is the comparison baseline.
warm-hit-prestagedFitCachePP's epoch 0: the file was pre-copied to a local tier, so the very first pass already faults from local NVMe/DRAM (not Lustre). Semantically a warm hit, temporally the first epoch. Tagged warm-hit-prestaged in the logs.
warm (page-cache resident)Epoch 1+: re-reading the same bytes when they are already in the OS page cache (applies to both sides).
amortizedTotal wall over all epochs including the one-time pre-stage cost; reported as a break-even-in-epochs view (see §3.6).
regime-pinnedPer-node working set is sized > node RAM (e.g. 640 GiB > 512 GiB) so neither side can hide the read behind the page cache — every epoch hits a storage tier. Prevents a page-cache artifact.
checksum gateThe hard correctness test: FitCachePP and Native must produce byte-identical checksums (per rank) over the same access plan, or the cell fails.

3. Common experimental machinery

3.1 Server launch & rendezvous

Servers run as a separate, backgrounded srun step alongside the benchmark step. Each node runs SERVERS_PER_NODE=4 server processes; TOTAL_SERVERS = N_NODES × 4. Port endpoints are written to .ports.cfg.$SLURM_JOBID under FitCache_PORTS_CFG_DIR, which the client reads to find servers.

# servers (backgrounded), then the benchmark step
srun -N $N_NODES -n $TOTAL_SERVERS --ntasks-per-node=$SERVERS_PER_NODE \
     --cpus-per-task=1 --cpu-bind=cores "$FITPP_SERVER_BIN" $TOTAL_SERVERS \
     > "$RESULTS_DIR/server.log" 2>&1 &
sleep 15                       # readiness (older scripts); scale-ladder polls the port-cfg file instead

scripts/frontier/frontier_sidecar_recovery.sh:136-139 · scale-ladder job.sh polls port-cfg (harness fix)

Note: for the warm-hit measurements the servers are not on the read critical path at all — the warm hit is a client-side resolver + local mmap (see §4–§6). Servers still run so the open-RPC/promotion path stays realistic.

3.2 Tier configuration & the deterministic hash-bin path

Two cache tiers are configured by env var; capacities are tuned per experiment (often DRAM is set tiny on purpose so the resolver lands on NVMe):

export FitCache_DRAM_PATH=/tmp/fitcachepp_<tag>_dram          # tmpfs (RAM-backed)
export FitCache_NVME_PATH=/mnt/bb/$USER/fitcachepp_<tag>_nvme  # burst-buffer NVMe
export FitCache_DRAM_CAPACITY=$((256*1024*1024))             # e.g. 256 MiB -> forces NVMe tier
export FitCache_NVME_CAPACITY=$((2000*1024*1024*1024))       # e.g. 2 TB
export FitCache_LOG_LEVEL=600    # verbose server logging
export FitCache_CROSS_JOB=0      # single-job mode for all reported experiments

Both the server (data mover) and the client (warm-hit resolver) compute the same deterministic cached path, so a pre-staged copy is found with no RPC. The path scheme (used by the pre-stage tool and the resolver alike):

// tools/fitcache_cached_path.cpp:14-19
size_t h = std::hash<std::string>(original_path);
subdir   = sprintf("%02zx/%02zx", (h >> 8) & 0xFF, h & 0xFF);
cached   = tier_base + "/" + subdir + "/" + basename(original_path);

3.3 Pre-staging (warm-hit setup)

To measure a warm hit, each node copies the files it will read from the PFS into its local tier at the resolver's hash-bin location, using the fitcache_cached_path tool. The pre-stage wall is reported separately (it is not charged as a cold epoch).

dst=$("$FITPP_REPO/tools/fitcache_cached_path" "$src" "$FitCache_NVME_PATH")
mkdir -p "$(dirname "$dst")"
if [ ! -f "$dst" ] || [ "$(stat -c %s "$dst")" != "$(stat -c %s "$src")" ]; then
  cp "$src" "$dst"        # whole-file copy; resolver gate is a full-size match
fi

frontier_megatron_warmhit_sweep.sh:75-86 · frontier_gnn_warmhit_sweep.sh:98-102

Gate is size-match, not content hash. The pre-stage / resolver acceptance test is "file exists AND size equals the original" — there is no per-file content hash at stage time. A corrupt same-size copy would pass the stage gate, but it would be caught end-to-end by the checksum-equality gate (§3.5), which compares the actual bytes touched against the native baseline.

3.4 Page-cache eviction (enforcing "cold")

Before a native cold measurement (and before each FitCachePP rep in the regime-pinned/scale-ladder runs), the page cache is flushed with a memory-pressure tool, benchmarks/util/mem_hog.c (allocate + touch every 4 KiB page of a large MAP_PRIVATE|MAP_ANONYMOUS region so the kernel evicts file-backed pages). A bounded loop reads Cached: from /proc/meminfo and hogs until it drops below a threshold:

evict_all() {  # scale-ladder, per node, before each rep
  srun --overlap -N $N -n $N --ntasks-per-node=1 --cpus-per-task=16 bash -c '
    for pass in 1 2 3 4 5; do
      cached_gb=$(awk "/^Cached:/{printf \"%d\", \$2/1048576}" /proc/meminfo)
      [ $cached_gb -le 8 ] && break        # target: Cached <= 8 GB
      hog=$((cached_gb+30)); per=$(( (hog+7)/8 ))
      for i in 1 2 3 4 5 6 7 8; do "$RESULTS_DIR/mem_hog" $per 1 >/dev/null 2>&1 & done; wait
    done'
}

megatron_scale_ladder/…/job.sh:43-59 · gnn_regime_pinned/…/job.sh:44-64 · benchmarks/util/mem_hog.c:64 · (older scripts also use posix_fadvise(POSIX_FADV_DONTNEED): frontier_llm_dataloader_compare.sh:107-120)

Eviction is best-effort. On 512 GiB nodes with a tiny working set (e.g. GNN touches only ~2.67 GB), mem_hog cannot always fully evict — so for GNN, rep 1 (cleanest eviction) is the anchor and rep 2/3 (which retained page cache) are kept for variance context only. Reproducers should verify /proc/meminfo.

3.5 The checksum-equality gate (correctness)

Every benchmark forces real byte reads with a vectorized sum and prints a GLOBAL_CHECKSUM per rank. The harness compares the full set of per-rank checksums (sorted rank=cksum pairs), not just rank 0 — FitCachePP and Native must match exactly, or the cell is a FAIL:

pairs() { grep 'SUMMARY' "$1" | sed -nE 's/.*rank=([0-9]+).*GLOBAL_CHECKSUM=([0-9]+).*/\1=\2/p' | sort -n; }
if [ "$(pairs native.log)" = "$(pairs fitcachepp.log)" ]; then echo "CHECKSUM_GATE: PASS"; else echo FAIL; fi

frontier_gnn_warmhit_sweep.sh:159-173 · frontier_megatron_warmhit_sweep.sh:127-132

The byte-touch differs slightly per workload (all reduce to an int64 to avoid overflow over TB-scale runs): Megatron sums a uint16 view; GNN sums a uint32 view masked to 63 bits; DINOv2 sums a uint8 view masked to 63 bits. The same dtype/view is used on both sides, so equality is exact. llm_coverage_bench.py:100 · gnn_feature_bench.py:198 · cc12m_mmap_bench.py:170

3.6 Two-view reporting (mechanism vs. amortized)

Each summary reports two views so the pre-stage cost is never hidden:

  • View 1 — warm-hit-only (mechanism): warm epoch vs native epoch, isolating the local-tier-mmap speedup.
  • View 2 — amortized incl. pre-stage: break-even epoch E where pre_stage + E·warm < E·cold, reported at E = 1…5.

frontier_dinov2_warmhit_sweep.sh:135-147

"Model" / access pattern

The "model" is a 2-hop heterogeneous graph sampler driving a sparse feature gather (no GNN layers, no training):

  1. Pick 1024 random seed papers (hop 0).
  2. Hop 1: sample ≤12 paper→paper neighbours + ≤8 paper→author neighbours (--fanout-pp 12 --fanout-pa 8).
  3. Hop 2: sample ≤8 paper→paper neighbours of the hop-1 papers (sub-sampled to ≤4096) (--fanout-pp2 8).
  4. Dedup the union of touched paper + author row ids; block-major mmap gather: partition rows by 12 GiB blocks (3,145,728 rows), mmap each block via offset, scatter-gather its rows, sum the uint32 view → masked checksum.

This touches only ~2.67 GB (~0.3 %) of the 902 GB corpus — the sparse, random, small-row access pattern that is pathological on Lustre. 20 batches × 1024 seeds per epoch.

gnn_feature_bench.py:36-58,190-203 · touched_rows/bytes in the run log

How we ran it (regime-pinned, 2026-06-14)

  • Node count: N=1; servers 4/node.
  • Pre-stage: the 6 feature+CSR files copied whole to /mnt/bb/$USER/… (whole-file because the resolver gate is a full-size match, and the random gather can touch any row).
  • FitCachePP arm: 2 epochs × 3 reps; mem_hog eviction before each rep. Epoch 0 = evicted NVMe-bound warm hit; epoch 1 = page-cache-resident reuse.
  • Native arm: run as separate single-rep jobs (gnn_nat1/2/3), 1 evicted epoch each — because one evicted native epoch alone takes 35–50 min.

"Model" / access pattern

The unit of work is a "shard pass", not a full-corpus epoch. Each rank mmap's its shard set and forces every byte through the page-fault path with a vectorized np.sum(dtype=uint64) over the whole shard. Two modes: disjoint (rank r reads shards [r·num_shards, (r+1)·num_shards)) or shared (--shared: all ranks read [0, num_shards)). A 1-in-50 PIL JPEG decode runs off the timed path as a secondary correctness signal (decode_ok count, e.g. 10956/10956).

There is no --seed in this bench: the access order is static and the checksum is the sum of fixed tar bytes, so it is deterministic by construction. cc12m_mmap_bench.py:81-97,156-199

How we ran it

  • Node counts: N=1 (and 2/4); servers 4/node; 2–3 shard-passes (pass 0 cold/warm-hit-prestaged, pass 1+ warm).
  • Pre-stage: each rank copies its shard set to /mnt/bb/$USER/… (or /tmp for the DRAM-tier proof, §9).
  • Native arm: mem_hog eviction before each rep so each native pass is genuinely cold.
  • Gate: per-rank GLOBAL_CHECKSUM equality + decode-success count.

7. Method variant — access-aware placement

Selects where a promoted file is cached. Two env knobs:

  • FITCACHE_MMAP_PLACEMENT = hash (default; modulo_select, scattered cluster-wide) or node_local (route promotion to a server on the requester's own node).
  • DINO_SHARD_MODE = shared (--shared) or partitioned (drop --shared → disjoint ranges) — drives the duplication-factor comparison.

The node-local routing math (block-distribution assumption):

// src/cross_job/fitcache_cross_job.cpp:121-158
int spn  = server_count / nnodes;          // servers per node; -1 (→ hash fallback) if not divisible
uint64_t h = fitcache_fnv1a64(path);
int slot = nodeid*spn + (h % spn);         // a server on THIS node (SLURM_NODEID)

Cells run (each measured by a resolver probe counting cache-hit vs fallback vs remote, plus the checksum gate): Megatron N=2 & N=4, GNN N=2, DINOv2 N=2 shared, DINOv2 N=2 partitioned (498 shards/node: node 0 reads [0,498), node 1 [498,996)), plus a hash baseline (Megatron N=2) to show the scatter.

8. Method variant — Megatron scale ladder (32–256 nodes)

  • Regime: 640 GiB/node (40 shards replicated), regime-pinned > 512 GiB RAM; FITCACHE_MMAP_PLACEMENT=node_local.
  • Per rep: mem_hog eviction on all nodes, then --num-shards 40 --coverage 1.0 --n-chunks 4000 --epochs 2 --seed 0.
  • Arms: Native = 1 rep × 2 epochs (cold-from-Lustre); FitCachePP = 2 reps × 2 epochs (epoch 0 = evicted NVMe-bound warm hit).
  • Every step uses srun --overlap to avoid step-creation deadlock.
  • Checksum gate gates the ladder: all native/warm_rep* logs must share one GLOBAL_CHECKSUM; a FAIL exit blocks the next-larger N via the SLURM dependency chain.
  • Walltime bins: learned empirically (e.g. 256 nodes needs 8 h — native epoch 0 reached ~98 min under contention).
srun --overlap -N $N -n $N --ntasks-per-node=1 --cpus-per-task=8 --cpu-bind=cores bash -c \
  '... llm_coverage_bench.py --num-shards 40 --coverage 1.0 --n-chunks 4000 --epochs 2 --seed 0 ...'
CKS=$(grep -h SUMMARY $RESULTS_DIR/{native,warm}_rep*.log | grep -oE 'GLOBAL_CHECKSUM=[0-9]+' | sort -u | wc -l)
[ "$CKS" = "1" ] && echo "CHECKSUM_GATE: PASS"

9. Method variant — DRAM-tier (tmpfs) proof

Shows the warm-hit path is tier-general, not NVMe-only. An 8-shard Megatron subset (128 GiB) is staged to /tmp tmpfs; the DRAM tier capacity is set large (160 GB) so the resolver lands on tmpfs, and a second arm uses NVMe (DRAM capacity 256 MiB). The intercept log shows WARM HIT … -> /tmp/… lines (48 hits), and both arms produce the bit-identical checksum 3453497658530916. A 4-arm probe (tmpfs-native ≈ nvme-native ≈ fitcache-dram) confirms the tiers tie here because the coverage bench is compute-bound (~4.4 GB/s).

10. Method variant — sidecar recovery (4 phases)

Tests that cache state survives a metadata-service restart. Driven by frontier_sidecar_recovery.sh for any of the three workloads (BENCH=megatron|gnn|dinov2):

  1. P1 Populate: server #1 up, run an organic cold epoch — open-time promotion copies files to the local tier and writes a .meta sidecar per file.
  2. P2 Kill: kill server #1, wipe the port-cfg.
  3. P3 Restart: server #2 up; restore_from_sidecars scans the tier dirs and rebuilds the cache map. The harness waits (≤120 s) for total restored = N in the server log.
  4. P4 Post-restart pass: re-run the bench over the same PFS paths; a resolver probe confirms every file warm-hits (hit==expected, fallback==0); checksum must equal the populate phase (both run --epochs 2 so the raw checksum is comparable).

A SKIP_POST=1 variant measures restore time only (the restore-scaling sweep over 32/256/996 objects).

11. Methodological honesty & known limitations

Stated plainly so the method is reproducible and not over-read:

  • Asymmetric baseline (intended). FitCachePP's measured epoch is a warm-hit-prestaged read of a local copy; the Native baseline is an organic cold read from Lustre (separately evicted). That is the question being asked (local tier vs PFS), and the checksum gate proves identical bytes — but it is not a warm-vs-warm comparison.
  • Eviction is best-effort. On 512 GiB nodes with a small working set (GNN ~2.67 GB), mem_hog cannot fully flush; the GNN headline uses rep 1 (cleanest eviction) as the anchor, with rep 2/3 retained only as variance context.
  • Native Lustre is condition-dependent. The same native epoch varies with cluster time-of-day contention (e.g. 944–2567 s at fixed N in the scale ladder). The warm side is the stable quantity; reported speedups inherit the native variance — hence the GNN result is given per regime (vs favorable vs cold Lustre) rather than a single ratio.
  • Pre-stage gate is size-match, not content hash (§3.3) — relies on the end-to-end checksum gate for integrity.
  • Working sets are sized > node RAM on purpose (regime-pinned) so the native baseline cannot hide reads in the page cache; a sub-RAM (partitioned) layout would let both sides page-cache and wash the gap out.
  • These are data-loading I/O benchmarks — the "model" is a deterministic access pattern + byte-touch, not a forward/backward pass. Claims are scoped to mmap-backed data loading, not end-to-end training.
  • Pre-stage cost is reported separately and folded back only in the amortized (View 2) break-even, never hidden inside a warm epoch.

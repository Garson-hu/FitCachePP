Prefetch-Informed Migration + Limited Replication — design

Status: implemented in src/comm and src/server (fitcache_prefetch_rpc_handler, fitcache_server_migrate_file, the replication_mode sidecar field), driven from the benchmarks through fitcache_prefetch_shim.py. Realizes the advisor direction (prefetch-informed migration via a new app interface + limited replication) so the cache is not fully replicated. Companion: implementation_walkthrough.html · experiments.html.

1. Goal & the one constraint that shapes it

Today every node caches its whole working set (N× replication). The goal is to keep the warm-hit speedup while storing each file once cluster-wide (1×), or a small bounded number of copies (k×) when needed. Two mechanisms:

  • Prefetch-informed migration — the app declares the files it is about to mmap; the system migrates the single cached copy to that node before the read.
  • Limited replication — a bounded copy count for hot / concurrently-read files (and for the un-partitionable GNN feature file).
The constraint: Frontier has no NVMe-oF / remote DAX, so a node cannot mmap a peer's NVMe directly. "Migration" = a network transfer of the file to the local tier. It is only worth it if it is prefetched and overlapped with compute; done lazily at mmap time it is no better than the existing per-read RPC fallback. This is why the prefetch interface is load-bearing, not cosmetic.

2. Flow

[dataloader] next epoch needs a,b → fitcache_prefetch(a,b)          (A) new API
       │ (overlapped with this epoch's compute)
       ▼
[server] prefetch RPC → remote_presence_map: a is on node X         (B) new RPC
       → peer-migrate RPC: pull whole file a from X to local NVMe    (C) NEW primitive
       → register path_cache_map + write sidecar(replication_mode)   (reuse)
       → source copy evictable (SINGLE_COPY) / kept (BOUNDED_k)      (E) new policy
       ▼
[client] mmap(a) → resolver stats local tier → local zero-copy mmap  (reuse, auto)

C. fitcache_server_migrate_file — the whole-file peer primitive implemented (the crux)

The one genuinely new mechanism, now in the tree (fitcache_data_mover.cpp:53). Before it, a remote cache hit was served as per-read bytes over RPC (one Mercury bulk per pread); there was no "pull the whole file from peer X to my local NVMe" op. It reuses the bulk-transfer plumbing and is invoked from the prefetch path (fitcache_server.cpp:237) and the open-time promote path (fitcache_data_mover.cpp:584).

4. Reused vs. new (effort)

Reused (already in tree)New (to build)
data_queue producer/consumer; path_cache_map; fs::copy+sidecar registration; Mercury bulk; peer_lookup; remote_presence_map; select_server_for_path; client resolver (auto-picks up the migrated file); refcount + eviction reaperpeer-migrate RPC + handler (whole-file transfer); prefetch RPC + client API; queue priority; replication_mode meta field + eviction-policy hook; a dataloader prefetch-hint shim

Verdict: the whole-file peer→local migration primitive landed as a ~200–300 LOC increment on existing infrastructure rather than a new subsystem, exactly as scoped; the experiments in experiments.html run on it.

5. Build order (incremental)

  1. Peer-migrate RPC (C) — the primitive; smoke-test "pull file from peer → local → mmap" on DINOv2 N=2.
  2. Prefetch API + RPC + priority queue (A,B,D) — proactive trigger.
  3. replication_mode field + eviction hook (E) — single-copy / bounded-k.
  4. Dataloader prefetch shim — feed per-epoch shard→node assignment.
  5. Reshuffle eval driver + metrics — exercises migration; measures aggregate-cache + hit-rate + read-time.

6. Scope — deliberately left to the later CXL multi-tier work

Automatic prefetch-hint inference (reuse-distance / ML); cluster-wide bounded-k census; over-capacity placement/eviction under pressure; multi-job sharing; preemption durability. TPDS delivers the limited version: an app-callable prefetch interface + JIT single-copy migration + a simple bounded-replication policy.
